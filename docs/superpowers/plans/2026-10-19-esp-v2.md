# ESP v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the ESP app into a pure-information people/animal recognizer: YOLO-pose + YOLO object detection, ByteTrack/Kalman tracking with predicted rendering, rule-based activity recognition, and HUD v2. Aim, game and health are removed.

**Architecture:** All decision logic lives in ESPCore and is unit-tested in WSL: YOLO decoding, NMS, Kalman, tracker, activity rules, stabilizers, events, trails, settings. The App target wires CoreML/Vision and SwiftUI and is verified by the CI build plus device gates.

**Tech Stack:** Swift 6.2/6.4, ESPCore (stdlib SIMD + Foundation), CoreML via Vision (`VNCoreMLRequest`), Ultralytics YOLO11n / YOLO11n-pose exported in CI, ARKit + LiDAR, SwiftUI Liquid Glass, XcodeGen, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-19-esp-v2-design.md` (v2). v1 spec `docs/superpowers/specs/2026-10-19-esp-camera-design.md` still governs everything v2 does not mention.

## Global Constraints

- All v1 Global Constraints still hold: iOS 26, landscape only, ESPCore has no Apple-framework imports, explicit public inits, commit trailer.
- Labels: `Người 01`, with numbers per kind in order of first confirmation, zero-padded to 2 digits. Animals use their Vietnamese name: `Chó 01`, `Mèo 01`.
- Detection thresholds:
  - pose box ≥ 0.35, NMS IoU 0.5, keypoint ≥ 0.5
  - ByteTrack high ≥ 0.5, low 0.15–0.5, IoU 0.2 (high) / 0.5 (low)
  - world match < 0.6 m
  - confirm 3 hits, lost after 0.7 s, forget after 10 s, max 30 tracks
- Activity thresholds exactly as spec §5. Stabilizer hold 0.4 s. Events: 1 per track per 2 s, show 5, TTL 8 s.
- Model input 640×480 (w×h). Compiled model names `yolo11n-pose.mlmodelc` and `yolo11n.mlmodelc`, in the bundle subdirectory `Models`.
- No `TodoWrite`-style tools. Progress lives in the ledger `.superpowers/sdd/2026-10-19-esp-v2/progress.md`.

## Review Focus

1. **Model files missing or failing to load on device** → app still runs on the Vision fallback and the menu shows a warning. Device check in Task 3.
2. **Pose output layout or dtype differs** (`[1,56,N]` vs `[1,N,56]`, Float16 vs Float32) → decoder still works. Test: Task 2 `decodesTransposedLayout`; App converts both dtypes.
3. **People crossing at walking speed** → IDs stay with the right person, thanks to Kalman prediction. Test: Task 4 `crossingPeopleKeepIds`.
4. **Upside-down orientation (landscapeLeft)** → activity rules see upright skeletons. Test: Task 5 `rulesWorkOnUpsideDownInput`.
5. **Old v1 settings file** (contains aimbot keys, preset `rage`) → loads as VIP without crashing. Test: Task 1 `v1SettingsFileLoads`.

### Task 2 (M9, Core): YOLO decoding, NMS, COCO classes, thermal v2

**Files:** Create `Core/Sources/ESPCore/YOLO.swift`, `COCO.swift`. Modify `ThermalPolicy.swift`, `VisionMapping.swift`. Tests: `YOLOTests.swift`, `ThermalPolicyTests` (rewrite in `SettingsTests` → move to `ThermalTests.swift`).

**Interfaces:**
- `public struct PoseCandidate: Sendable { box: Rect; confidence: Float; joints: [Joint: Vec2] }` — normalized to the model input, top-left origin.
- `public enum YOLO`:
  - `static func decodePose(_ values: [Float], shape: [Int], inputSize: Vec2, boxThreshold: Float = 0.35, iouThreshold: Float = 0.5, keypointThreshold: Float = 0.5) -> [PoseCandidate]`
    - Accepts `shape == [1, 56, N]` or `[1, N, 56]`.
    - Per anchor: cx, cy, w, h (pixels), conf, then 17 × (x, y, c) in COCO order.
    - Adds `.neck` and `.root` as the midpoints of the shoulders and hips when both sides pass the keypoint threshold.
    - NMS, then results sorted by confidence.
  - `static func nms(_ boxes: [Rect], scores: [Float], iouThreshold: Float) -> [Int]` — indices kept, highest score first.
- `public enum COCOClass: Sendable, Equatable { case person, animal(AnimalKind), object(ObjectKind), other }` with `init(label: String)`, using the 80 COCO label strings.
- `public enum ObjectKind: String, CaseIterable, Sendable`: phone (`cell phone`), cup, bottle, wineGlass (`wine glass`), laptop, book, umbrella, ball (`sports ball`), chair, couch, bench, bed, backpack, handbag, bicycle, motorcycle — each with `name`/`emoji`.
- `public struct DetectedObject: Sendable { kind: ObjectKind; box: Rect; confidence: Float }` (captured-image coordinates).
- `VisionMapping.topLeftPoint(_:orientation:)` / `topLeftRect(_:orientation:)`: `.up` is the identity, `.down` maps (x, y) → (1−x, 1−y).
- `PerceptionBudget { poseHz; objectHz; chamsAllowed; showHeatWarning; hudHz }`:
  - `ThermalPolicy.budget(_ level:, isRecording:, smoothMode:)` per spec §7
  - nominal pose is 60 when `smoothMode`
  - recording caps pose at 24
  - `hudHz` is 60, or 30 at serious/critical

  - on `YOLOPerception() == nil` it falls back to the existing Vision `PerceptionPipeline` and sets `store.modelWarning = true`

### Task 4 (M10, Core + App): Kalman, ByteTrack, predicted rendering

**Files:**
- Create: `Core/Sources/ESPCore/Kalman.swift`
- Modify: `Tracker.swift`, `Track.swift`, App `ESPLayout.swift`
- Tests: `KalmanTests.swift`, `TrackerTests.swift`

**Interfaces:**
- `public struct KalmanCV<V: SIMD & Sendable>: Sendable where V.Scalar == Float`
  - `init(position: V, processNoise: Float, measurementNoise: Float)`
  - `mutating func predict(dt: Float)`
  - `mutating func update(_ z: V)`
  - `var position: V`, `var velocity: V`
  - Per-lane constant-velocity filter with a 2×2 covariance.
- Tracker:
  - Box Kalman on (cx, cy, w, h), predicted to the current time before association.
  - Two-stage association (high then low confidence), same kind only, then world distance.
  - Low-confidence detections never start tracks.
  - World Kalman on the feet position gives `velocity`.
  - Joints keep the OneEuro filters. Yaw and height smoothing stay.
  - Max 30 tracks.
- `Track.predictedWorld(at time: TimeInterval) -> Vec3?` = position + velocity × clamp(time − lastSeen, 0, 0.3).
- ESPLayout: the now-anchor uses `predictedWorld(at: currentFrame.timestamp)`.

  - `crossingPeopleKeepIds`: two people walk past each other horizontally and the ids stay with their own direction
